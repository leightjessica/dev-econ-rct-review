# Project memo: Identifying development RCTs in top economics journals, 2021-2025

**Last updated:** 2026-07-22
**Owner:** Jessica Leight (J.Leight@cgiar.org)
**Project root:** `~/IFPRI Dropbox/Jessica Leight/dev-econ-rct-review/`

## 1. Objective

We aim to construct a replicable dataset of all randomized controlled trials in development economics published in a defined set of leading economics journals over 2021-2025. The end product is a single CSV in which every row is one published article, with flags for (a) whether the paper falls within development economics and (b) whether the paper reports an RCT. The dataset is intended to be shareable with other researchers, so every step is designed to run from a clean clone of the project folder using publicly accessible inputs wherever feasible.

## 3. Key decisions

The following decisions were made at project inception and are recorded here so future re-runs are interpretable.

- **Development scope.** A paper is classified as development if any of the following holds (rules evaluated in order; first match wins): (i) the journal is JDE; (ii) at least one JEL code is in **O1 (Economic Development) or O2 (Development Planning and Policy)**; (iii) the article's title or abstract mentions a low-, lower-middle-, or upper-middle-income country (per the World Bank classification) or a developing-region term such as "Sub-Saharan Africa" or "developing countries". Rule (ii) was tightened from an earlier draft that also accepted O3 (Innovation), O4 (Growth), and O5 (Country Studies) codes; spot-checking revealed that O3/O4 codes routinely appear on innovation and growth papers based in high-income countries (e.g., AER's "Market Power and Innovation in the Intangible Economy" using French and US data), and that O5 codes were always co-assigned with O1/O2 in our sample, so adding them would not have changed the result. Rule (iii) was added because the Stage 1 abstract pull plus the JEL-code merge missed papers that name a developing country directly in the abstract but were never indexed in EconLit (e.g., empirical papers in RESTAT and EJ where EconLit's DOI population is sparse). Borderline cases — papers that satisfy none of the three rules but might still be development — are escalated to LLM classification of the abstract (Stage 3a) for a yes/no/uncertain judgment.
- **RCT scope.** We classify a paper as an RCT if it reports the results of a real-world randomized intervention. This includes individual-randomized RCTs, cluster RCTs, encouragement designs, RCTs of one component within a larger program, and long-run follow-ups of prior RCTs (the latter flagged as a distinct subtype). Lab-in-the-field experiments are excluded **unless** they involve a real-world manipulation of incentives, information, or services that participants experience outside the experimental setting.
- **Output format.** Single CSV (UTF-8). Optionally also a Stata `.dta` if requested.
- **Execution environment.** Local, on Jessica's Windows machine. Python 3.14.x. Stage 1 uses standard library only; later stages introduce a small set of pinned dependencies (`requirements.txt`). The working interpreter is a per-user install at `C:\Users\JLEIGHT\AppData\Local\Python\pythoncore-3.14-64\python.exe`; the bare `python`, `py`, and `python3` names on the `PATH` are Microsoft Store "App execution alias" stubs that do not run, so every script must be invoked through the full path above (see the README "Python interpreter on the development machine" section). The path can be re-derived on any machine via `(Get-ItemProperty 'HKCU:\SOFTWARE\Python\PythonCore\3.14\InstallPath').'(default)'`.
- **Inputs stay inside the project folder (project lead, 2026-10-21).** Every input a script reads must live inside `dev-econ-rct-review/` (typically under `data/`, or in a folder at the project root such as `World Bank subnational data/`). Scripts must not read from, and analysis must not draw on, sibling folders elsewhere in the Dropbox (for example the separate "RCT Registry Project" or "RCT Tracking Data Collection" folders), even where they hold a relevant file; when an external dataset is needed, a fresh copy is downloaded into the project and its provenance recorded here. This keeps the project self-contained for replication and avoids dependence on folders whose contents may change or carry different access terms.
- **Sharing.** The project folder is structured so that any collaborator with Python and an Anthropic API key (for Stage 3) can re-run end-to-end. Raw data exports from EBSCO/EconLit (Stage 2) are licensed and therefore checked into the project as derived JEL-code lookups rather than full record exports; this is documented in the README.

## 4. Workflow

The core dataset-construction pipeline has six stages (numbered 0, 0b, 1, 2, 3a, 3b, 4, 5). Each stage produces a standalone CSV; each subsequent stage takes the previous stage's CSV as its only input. This makes any stage independently re-runnable and any intermediate state inspectable. A series of optional add-on analyses build on the assembled dataset and are documented in their own sections below: topic classification (Stages 3c-3d, 7, 10), country representation and funders (Stage 6 family, 11), author gender (Stages 8-9), IRB / ethics-approval attribution (Stages 12-15, Section 10), and acknowledgments / seminars (Stages 16-18, Section 11).

### Stage 0 — Bootstrap: JEL descriptor → code lookup

`scripts/00_build_jel_lookup.py` fetches the AEA's authoritative JEL classification (https://www.aeaweb.org/econlit/jelCodes.php?view=jel) and writes `data/jel_lookup.csv` with one row per leaf code (856 in total) and both bare and prefixed descriptor forms. Stage 2 uses this lookup to map EconLit's descriptor strings (e.g., "Microeconomic Analyses of Economic Development") back to JEL codes (e.g., "O12").

### Stage 0b — Bootstrap: LMIC country list

`scripts/00b_build_lmic_countries.py` fetches the World Bank's country classification by income level via the WB API and writes `data/lmic_countries.csv` with one row per country in LIC, LMIC, or UMIC plus a curated set of region terms ("Sub-Saharan Africa", "developing countries", etc.) and common name variants ("Russia" alongside "Russian Federation"; "Cote d'Ivoire" alongside "Côte d'Ivoire"; etc.). Stage 2 uses this list to apply the country-mention rule of the development filter.

### Stage 1 — Metadata acquisition (multi-source)

Stage 1 is implemented as a chain of three scripts. Each successive script attempts to fill abstracts for rows where the prior script found none, recording the provenance of every abstract in an `abstract_source` column. This chain is necessary because the three largest publishers in the journal list (Elsevier for JDE, Wiley for Econometrica, University of Chicago Press for JPE) restrict abstract redistribution under their licensing agreements with both OpenAlex and Crossref. We discovered this empirically during Stage 1b: of 1,115 OpenAlex-missing abstracts, Crossref recovered only 21.

**Stage 1a — OpenAlex pull.** `scripts/01_openalex_pull.py` queries the OpenAlex Works API by ISSN and publication year for each of the twelve journals, paginates through results with cursor-based pagination, and writes one row per article to `data/raw_openalex_2021_2025.csv`. Captured fields include DOI, title, abstract (reconstructed from OpenAlex's inverted index), authors, journal name, ISSN, publication year/date, volume, issue, page range, and OpenAlex document type. A UTC snapshot timestamp is recorded on every row. The "polite pool" mailto header is set; OpenAlex rate-limits cooperatively in this mode (~10 req/sec, 100,000 req/day). Standard-library only.

**Stage 1b — Crossref backfill.** `scripts/01b_crossref_abstract_backfill.py` queries the Crossref Works API by DOI for every row missing an OpenAlex abstract. Crossref returns abstracts as JATS-tagged HTML; tags are stripped. Output: `data/raw_with_abstracts_2021_2025.csv` (also tracked thereafter as the "running" file). Standard-library only.

**Stage 1c — Semantic Scholar backfill.** `scripts/01c_semantic_scholar_backfill.py` queries the Semantic Scholar Graph API batch endpoint (up to 500 DOIs per request) for any rows still without an abstract. Updates `data/raw_with_abstracts_2021_2025.csv` in place. Standard-library only. No API key required at our query volume; we run at ~1 batch/sec.

**Stage 1d — EconLit backfill (deferred to Stage 2).** Any rows still missing abstracts after 1a-1c — primarily JDE articles given Elsevier's licensing posture — are backfilled from EconLit when the EBSCO export is performed for JEL codes (Stage 2). EconLit records include both abstracts and JEL codes, so a single export serves both purposes.

**Stage 1e — Manual residual.** Any rows still missing abstracts after 1d are flagged for manual retrieval from the publisher's website, restricted to development-tagged rows that survive Stage 2 filtering. This minimizes manual work to the actually-relevant subset.

The `abstract_source` column takes values `openalex`, `crossref`, `semantic_scholar`, `econlit`, `manual`, or one of the `none_*` flags indicating why no abstract is available.

### Stage 2 — Development-topic filtering

`scripts/02_dev_filter.py` reads all CSVs from `data/EconLit/`, restricts to the twelve in-scope journals (matched by ISSN, not by title — see EconLit export doc for why this matters), parses each row's `subjects` field by splitting on " ; ", and resolves descriptors to JEL codes via the Stage-0 lookup. Three indexes are built for the EconLit→OpenAlex merge — by DOI, by `(journal, volume, issue, first_page)`, and by `(journal, normalized_title)` — to handle the fact that EconLit DOI population is uneven across publishers (100% for AEA journals; 1-30% for UChicago, Wiley, MIT). The merge tries DOI first, then bibliographic tuple, then title; this raises end-to-end EconLit-to-OpenAlex match coverage from 43% (DOI alone) to 84% in our 2026-05-07 run.

In parallel with the EconLit merge, Stage 2 builds a single case-insensitive word-boundary regex over the LIC/LMIC/UMIC country names and region terms loaded from `data/lmic_countries.csv` (Stage 0b) and scans each row's title and abstract for any country mention. The matched term and its source field (`title` vs `abstract`) are recorded in `country_match` and `country_match_in` columns.

The development filter is then applied as a five-rule decision tree, evaluated in order, with the `dev_filter_source` column recording which rule fired:

1. The journal is **JDE** → `is_development = TRUE`, `dev_filter_source = jde_inclusion_rule`
2. The article carries at least one JEL code beginning with **O1 or O2** → TRUE, `jel_o1_o2_code`
3. The title or abstract mentions an LMIC country or developing-region term → TRUE, `country_match`
4. EconLit returned JEL codes, none in O1 or O2, and no country mention → FALSE, `jel_no_dev`
5. No EconLit JEL codes available and no country mention → BORDERLINE, `no_signal` (or `econlit_no_jel` if the row was matched to EconLit but its `subjects` field was empty)

The `jel_codes_o_only` diagnostic column preserves the broader O-family code set (O1-O5) for audit purposes; the binding filter uses `jel_codes_o12_only`. Stage 2 also backfills any abstracts still missing after the Stage 1 chain from EconLit's abstract field (this is Stage 1d, deferred to Stage 2 because the EBSCO export is the authoritative source for both JEL codes and abstracts).

Output: `data/dev_filtered.csv`.

### Stage 3a — LLM classification of borderline rows

`scripts/03a_dev_borderline_classify.py` reads `dev_filtered.csv`, identifies rows with `is_development == 'BORDERLINE'` of type `article` with non-empty abstracts, and asks the Anthropic API (default: `claude-sonnet-4-5`) to classify each as development / not / uncertain. The system prompt is cached (5-minute TTL) for cost efficiency; `temperature = 0` for determinism. Each classified row records the model identifier, prompt version, and the LLM's one-sentence justification. Output: `data/dev_classified.csv`.

The script is **resumable** — rerunning skips rows already classified — and writes a checkpoint every 50 calls.

### Stage 3b — LLM classification of RCT status

`scripts/03b_rct_classify.py` reads `dev_classified.csv` (or `dev_filtered.csv` if 3a was skipped), filters to development papers of type `article` with non-empty abstracts, and asks the LLM to classify each as RCT / not / uncertain with subtype (`individual`, `cluster`, `encouragement`, `sub_component`, `follow_up`, `field_experiment`, `n/a`) and self-reported confidence. The prompt encodes the project's RCT definition: cluster, encouragement, sub-component, and long-run follow-up RCTs all qualify; lab-in-the-field is excluded unless real-world manipulation is involved. Output: `data/rct_classified.csv`.

A second pass that fetches article introductions for "uncertain" rows is scaffolded but deferred to a later iteration; uncertain rows are flagged in the output for manual review.

### Stage 3c — LLM classification by substantive topic

`scripts/03c_topic_classify.py` reads `data/final_dataset.csv` and assigns each development paper a primary and (optional) secondary code from a 16-element topic taxonomy: `agriculture, health, education, labor, firms, finance, social_protection, gender, political_economy, conflict_crime, environment, trade_macro, migration, infrastructure, behavioral_info, other`. Unlike Stages 3a and 3b, which use the Anthropic Python SDK, Stage 3c shells out to headless `claude -p` (authenticating via the user's local subscription OAuth) and pins the model to `claude-haiku-4-5-20251001`; structured output is enforced via `--json-schema`. The script is resumable, parallelized at four workers, and checkpoints every 50 calls. Output: `data/topic_classified.csv` (one row per development paper, with `primary_topic`, `secondary_topic`, `topic_confidence`, `topic_justification`, `topic_llm_model`, `topic_prompt_version`).

### Stage 3d — Blind-coding validation of Stage 3c

`scripts/03d_topic_validate.py` runs in two modes. BUILD mode (default) draws a stratified random sample of N papers (default 50) from `topic_classified.csv` — stratified by LLM primary topic, two papers per code with the residual filled proportional to code size — and writes `data/topic_validation_blind.csv` with the paper's bibliographic metadata, title, abstract, and three blank human-coder columns (`primary_topic_human`, `secondary_topic_human`, `notes`); the LLM's classification is NOT present in the blind sheet, to avoid anchoring. A companion `data/topic_validation_codebook.md` is written as a one-page cheat sheet of the 16 codes. REPORT mode (`--report`) merges human and LLM codes after the sheet is filled in, computing primary and secondary agreement, per-code precision and recall, a confusion matrix, and a side-by-side disagreement listing. Output: `data/topic_validation_report.md`.

### Stage 4 — Output assembly and summary

`scripts/04_assemble.py` reads the latest available output (rct_classified > dev_classified > dev_filtered, in priority order), filters to `is_development == 'TRUE'` AND `type == 'article'`, and writes `data/final_dataset.csv` with the columns documented in `docs/codebook.md`. A second output, `data/summary_journal_year.csv`, is a wide table of counts per journal-year (development total, RCT yes / no / uncertain). A SHA-256 of each output is logged for reproducibility verification.

### Stage 5 — Figures

`scripts/05_make_charts.py` reads `data/final_dataset.csv` and writes five publication-quality figures to `data/figures/`, each as PNG (300 dpi raster) and PDF (vector for inclusion in LaTeX manuscripts):

1. `fig1_rct_share_by_journal` — horizontal bar of RCT share per journal, with absolute counts annotated
2. `fig2_rct_share_by_year` — line chart of overall RCT share by publication year
3. `fig3_rct_share_by_year_journal` — small multiples by journal × year
4. `fig4_rct_subtype_distribution` — bar chart of the six RCT subtypes (individual, cluster, encouragement, sub-component, follow-up, field experiment)
5. `fig5_dev_papers_by_year_stacked` — stacked bars of development articles per year, split by RCT yes / not RCT / unclassified-no-abstract

Stage 5 has one external dependency (`matplotlib`); all other stages are stdlib-only or use `anthropic`.

## 6. Replicability and sharing

We have followed several conventions to keep the project shareable.

- **Stdlib-only Stage 1.** No external dependencies are required for the metadata pull, so a collaborator can re-run Stage 1 with only a working Python install.
- **Pinned dependencies.** Stages 2-4 list dependencies in `requirements.txt` with explicit version pins.
- **Snapshot timestamps.** Every Stage 1 row records the UTC time at which OpenAlex was queried. Re-running on a different day may yield small differences as OpenAlex's coverage updates; the timestamp makes such drift explicit.
- **Deterministic LLM calls.** Stages 2-3 set `temperature = 0` and record the model identifier and prompt version on every row, so classifications are reproducible to within Anthropic's model-version stability guarantees.
- **Licensed inputs.** EconLit/EBSCO output is licensed and is not redistributed. Collaborators who wish to re-run Stage 2 must perform their own EBSCO export following the documented procedure.
- **No raw PDF redistribution.** Where Stage 3 fetches article introductions, only the small text excerpts strictly needed for classification are stored (in the run log) and never the full article content.
- **Versioning.** The project folder can be initialized as a git repository at any time; data files in `data/` are large and may be excluded via `.gitignore` if shared via GitHub. For Dropbox-based sharing, the entire folder is portable.

## 7c. Topic-classification validation (2026-05-22)

We drew a 50-paper stratified random sample (seed 42; two papers per LLM primary code where available, with the residual filled proportional to code size) from `topic_classified.csv` and blind-coded 49 of the 50 against the 16-code taxonomy. The 50th, the ACA paper described in Section 7a, was retained for the manual exclusion rather than re-coded. After canonicalizing the human codes to match the LLM's underscored variants (`political economy → political_economy`, `social protection → social_protection`, `trade_ macro → trade_macro`, `behavioral → behavioral_info`, `credit → finance`, `educatiion → education`), headline agreement on primary topic was **65.3% (32/49)** and on exact-match secondary topic was **34.7% (17/49)**. The pre-normalization raw figure of 49.0% understated accuracy, with much of the apparent disagreement reflecting label drift in the human sheet rather than substantive mismatch.

Per-code patterns from the 49-paper sample (precision / recall, primary topic):

- High-precision, high-recall: `education` (100% / 80%), `health` (75% / 100%), `social_protection` (100% / 67%), `political_economy` (67% / 80%).
- High precision but low recall: `gender` (100% / 40%). The LLM correctly tags gender-framed papers it identifies, but misses dowry, IPV, marriage-market, and women's-decision-making papers, routing them into `finance`, `behavioral_info`, or `conflict_crime`.
- Low precision, high recall: `behavioral_info` (25% / 100%). The code is over-assigned, absorbing labor, gender, and finance papers in which information provision is the mechanism rather than the substantive outcome.
- Substantive disagreement patterns from the 17 remaining mismatches: regulatory analyses of financial and macroeconomic policy routed to `political_economy` rather than `finance` or `trade_macro`; informal community-monitoring interventions (e.g., a Sierra Leone CDD aid evaluation; a Uganda livestock-monitoring program) classified as `political_economy` when the substantive outcome was infrastructure, social protection, or agriculture; and methodology papers (cell-phone-record commuting measurement) coded to the substantive domain of the data rather than `other`.

We assess that the substantive disagreements are concentrated in a small number of taxonomic ambiguities and are amenable to a targeted prompt revision; see Section 9.

## 8. Known limitations

- OpenAlex abstract coverage is incomplete for some recent journal issues; the Stage 1b-1d backfill chain reduces the gap to roughly 6% of articles, with the residual concentrated in ECMA, JPE, and JDE (publishers that restrict abstracts to indexing services).
- EconLit JEL code coverage lags publication by several months; the most recent issues (late 2025) may not yet have JEL codes assigned. The country-mention rule (Stage 2 step iii) and the borderline LLM classifier (Stage 3a) together catch these cases.
- LLM classification of RCT status is highly accurate from abstracts when the design is clearly described, but some abstracts use ambiguous language (e.g., "we randomize the order of survey questions" — not an RCT in our sense). The subtype taxonomy and the explicit "field_experiment" vs "n/a" distinction are intended to surface these. Six rows in our 2026-05-07 run were classified `uncertain` and are flagged for manual review.
- The country-mention rule uses bare country names with `\b` word-boundary matching. It catches "China" in "China's growth" but NOT "Chinese" in "Chinese economy" (the adjective form). It also does not include the bare term "Africa" (which our regex specifically excludes to avoid false positives from "African Americans" — though `\b` would in fact preclude that match; this conservative choice could be revisited in a v2 release). A handful of papers (~6 in our sample) were caught only by Stage 3a's LLM classifier, not by the structural country rule, because they used adjective forms or referred to "Africa" without a country name.
- The development scope is conservative on the JEL side (O1 + O2 only). A v2 could explore including specific O5 country-study codes (O53 Asia, O54 Latin America, O55 Africa) as additional inclusion signals, though in our 2026-05-07 sample no paper carried an O5 code without also carrying an O1 or O2 code, so this would have made no difference.
- The O1 + O2 inclusion rule is also vulnerable to JEL false positives — papers carrying O1- or O2-family codes that are not development by substantive content. The 2026-05-07 run produced one such case (DOI `10.1093/restud/rdae020`, "Estimating Equilibrium in Health Insurance Exchanges: Price Competition and Subsidy Design under the ACA", a US ACA paper carrying O15 and O16 codes), which was manually excluded on 2026-05-22 (Section 7a). The O15 (Human Resources; Income Distribution) and O16 (Financial Markets; Capital Investment) codes appear most prone to this misassignment because they map to substantive topics that are also studied extensively in high-income contexts. We assess that future re-runs should re-screen O1/O2-only inclusions (i.e., those without an LMIC country signal) for false positives, either via a brief LLM pass or a manual review of the residual list.

The four refinements (with proposed edits to the `USER_INSTRUCTION` block):

1. **Measurement papers route to `other`.** When the paper's headline contribution is improving the measurement of a phenomenon rather than estimating a treatment effect or a substantive relationship, the primary code is `other` regardless of the domain measured. Example from the validation set: "Measuring Commuting and Economic Activity inside Cities with Cell Phone Records" (RESTAT 2021) infers spatial income from cell-phone data; the contribution is methodological, so primary should be `other`, not `labor` or `infrastructure`. *Proposed edit:* append to DISAMBIGUATION — "Papers whose headline contribution is improving the measurement of a phenomenon (rather than estimating a treatment effect or a substantive relationship) => primary=other, regardless of the substantive domain of the measured object."

2. **Expand `gender` triggers.** The `gender` code should fire whenever any of the following is the substantive focus (not merely a heterogeneity cut): dowry, marriage markets, intimate partner violence (IPV), women's empowerment, female genital mutilation (FGM), women's decision-making, or intra-household allocation when the gender lens is central. For IPV specifically, the secondary code should be `conflict_crime`. Validation-set examples currently misclassified: "Saving for dowry: Evidence from rural India" (JDE 2021, LLM=finance), "Culture and the Historical Fertility Transition" (RES 2022, LLM=behavioral_info), "Dynamic Impacts of Lockdown on Domestic Violence in Chile" (RESTAT 2024, LLM=conflict_crime). *Proposed edit:* replace the `gender` entry in CODE GUIDE with — "gender: women's empowerment, dowry, marriage markets, intimate partner violence (IPV), female genital mutilation (FGM), women's decision-making, intra-household allocation when the gender lens is central, GBV. 3. **`political_economy` requires formal governing actors as primary.** As primary, the code should be reserved for papers whose substantive focus is the behavior of elected or appointed officials operating within formal governing institutions — corruption among public officials, elections, state capacity, bureaucracy, or formal governance reforms. Informal-institution interventions (community monitoring, social accountability committees, village-level mobilization, community-driven development aid) should use the substantive outcome code (`infrastructure`, `education`, `agriculture`, `social_protection`, `health`) as primary, with `political_economy` available as secondary if institutional change is part of the intervention. Use as primary only when the focus is on formal political actors and institutions; informal community-monitoring or social-accountability interventions belong under their substantive outcome code, with political_economy as a secondary code at most."

4. **Regulatory policy in finance/macro/trade stays in those buckets.** Analyses of regulatory policy concerning financial markets, macroeconomic policy, or trade policy should be classified as `finance`, `trade_macro`, or the appropriate substantive code as primary. `political_economy` is appropriate only when the paper's lens is explicitly on the decision-making of the political actors who set the regulation, not when the lens is on the regulation's economic effects. Validation-set example: "China's Model of Managing the Financial System" (RES 2021; finance/political_economy by the LLM, finance by the human coder). *Proposed edit:* append to DISAMBIGUATION — "Regulatory policy analyses concerning financial markets, macroeconomic policy, or trade policy => use the substantive code (finance, trade_macro) as primary; political_economy is appropriate only when the paper's lens is explicitly on the decision-making of the political actors who set the regulation, not on the regulation's economic effects."

The proposed edits are mechanical and can be applied by a focused edit pass on `scripts/03c_topic_classify.py`. ## 10. IRB / ethics-approval attribution (Stages 12-13)

A separate line of analysis, begun 2026-06-09, examines the research-ethics governance of the 392 RCTs: whether each paper reports any ethics oversight, and — the question of substantive interest — whether the approving body is located in the country where the data were collected, as opposed to a (frequently high-income) home institution of the researchers. The exercise is implemented as a two-script pipeline that separates deterministic text location (Stage 12) from interpretive extraction (Stage 13).

### Stage 12 — Keyword scan for IRB / ethics text

`scripts/12_irb_extract.py` is a keyword/regex scanner, not an interpreter. For every RCT with a matched full-text PDF, it locates any reference to research-ethics oversight anywhere in the paper (not only the acknowledgments), because economics papers place these statements unpredictably (a page-one title footnote, a "Declarations"/"Ethics" section near the references, a data or online appendix, or a sentence inside the experimental-design section). The terms searched are IRB, Institutional Review Board, ethical/ethics, ethical/ethics approval, and human subjects. Two robustness features matter: whitespace (including newlines that split a phrase across two lines) is collapsed before matching, and a secondary "despaced" scan handles Elsevier (JDE) extractions that lose all inter-word spaces (so "institutionalreviewboardofmcgilluniversity" still matches). Each RCT is matched to a PDF by the existing 06d match report, then a DOI sniffed from the first pages, then a normalized-title substring fallback. Output: `data/irb_mentions.csv`, one row per RCT, with `extraction_status` in {`ok`, `no_mention`, `no_pdf`, `pdf_error`}, the terms matched, the pages hit, and excerpted snippets. The script is resumable (it re-scans only newly matched PDFs).

The most recent completed run (2026-06-09) covered the 392 RCTs and matched a PDF to 389 of them, of which 242 (62 percent) contained at least one IRB or ethics mention and 147 did not. Three RCTs were unmatched (`no_pdf`): `10.3982/ecta19127`, `10.1016/j.jdeveco.2022.102990`, and `10.1016/j.jdeveco.2025.103690`. The full text for all three has since been added to `fulltext/` (403 PDFs now on disk, up from 400), so a re-run is expected to resolve them and classify all 392 RCTs.

On 2026-06-09 we also widened the snippet windows so the downstream Stage-13 pass has enough context to read the approving institution's name (which often sits a clause away from the keyword): `SNIPPET_PAD` was raised from 140 to 240, the despaced padding was raised from 60 to 120 (new `DESPACED_PAD` constant), and `MAX_SNIPPETS` from 8 to 14. Because the resume logic reuses previously stored snippets, a re-run that is to produce uniformly wide snippets must first move the existing `data/irb_mentions.csv` aside so every row is rebuilt at the new width (a full PDF re-read is needed in any case to pick up the three added papers).

### Stage 13 — LLM extraction of IRB location (NEW; not yet run)

`scripts/13_irb_classify.py` is the structured-interpretation pass that sits downstream of the Stage-12 scanner. It reads the snippets in `irb_mentions.csv` and, for each RCT with a mention, asks the Anthropic API (default `claude-sonnet-4-5`, matching Stages 3a/6a; `temperature = 0`; cached system prompt) to extract every named approving body and the ISO 3166-1 alpha-3 country code of each. The division of labour is deliberate: the model performs EXTRACTION only, and the study-versus-IRB COMPARISON is computed deterministically in Python (set membership of ISO3 codes against the study country from Stage 6a's `country_classified.csv`), so the headline classification is reproducible and not at the mercy of the model's arithmetic. The prompt encodes the project-specific rules we care about — mapping institution names to countries (for example, Columbia to USA, McGill to CAN, Innovations for Poverty Action's IRB to USA, University of Nairobi to KEN), treating a study's home-institution IRB and any local ethics board as separate entries, and explicitly ignoring trial registries (AEA RCT Registry, ClinicalTrials.gov, ISRCTN, RIDIE), which are registrations rather than ethics approvals.

Output: `data/irb_classified.csv`, one row per RCT, carrying the study country (`study_setting`, `study_iso3_list`), the Stage-12 status, the extracted `irb_institutions` and `irb_iso3_list`, the boolean `irb_in_study_country`, a per-paper `irb_location_class`, the count of institutions, a bonus `irb_approval_status` (`approved`/`exempt`/`mentioned_only`/`unclear`), and the model and prompt-version stamps. The classification scheme (study country defined as the data-collection country) is:

- `local_only` — every identified IRB is located in the study country;
- `foreign_only` — every identified IRB is outside the study country (for example, a US or European home institution);
- `both` — at least one IRB in the study country and at least one outside;
- `undetermined` — an IRB is mentioned but no institution or country is identifiable, OR the study country itself is not a single identifiable country (the cross-country / no-country / unlisted cases, distinguishable via the `irb_country_identified` flag), so no comparison is possible;
- `no_mention` / `no_pdf` — carried through from Stage 12 for completeness, so the output covers all 392 RCTs.

The raw `irb_iso3_list` and `study_iso3_list` are retained on every row, so any case classed `undetermined` for want of a single study country can be re-derived by hand. The script is resumable (it skips RCTs that already carry a non-empty `irb_location_class`), checkpoints every 25 calls, and honours a `SMOKE_N` environment flag for a quick validation pass.

## 11. Acknowledgments and seminars (Stages 16-18)

A further line of analysis, begun 2026-06-22, characterizes the acknowledgments footnote of each of the 392 RCTs along two dimensions of substantive interest: the number of individuals personally thanked for intellectual input, and the number of distinct named seminars, conferences, and workshops whose audiences are thanked. The motivation is to document, descriptively, the scale of the informal collaboration and dissemination network on which a published development RCT now rests (a quantity that is plausibly related to authors' professional networks and to the seminar circuit a paper must clear before publication). Per the project lead's specification (2026-06-22), the headline individual count is restricted to named natural persons thanked for comments, discussion, or advice; research assistants, anonymous referees, and the editor are captured in separate fields and deliberately excluded from the headline, so that the count measures intellectual feedback rather than production labour or editorial process. The seminar count combines seminars, conferences, workshops, symposia, and named annual meetings into a single tally of distinct named venues, and a vague reference with no named venue ("various seminars") is flagged (`seminars_unspecified`) rather than assigned a guessed count. The exercise reuses the full-text corpus and the DOI-to-PDF map already assembled for the IRB work (Stage 12), so no new PDF matching is required.

The pipeline separates deterministic text location from interpretive counting, mirroring the Stage 12/13 division of labour. Stage 16 (`scripts/16_ack_extract.py`) is a locator: using poppler's `pdftotext` (chosen over `pdfplumber` here because its clean UTF-8 output preserves accented names intact, which matters for name counting, and it reads a whole paper in well under a second), it isolates the acknowledgments block from each PDF by anchoring on the earliest of a set of standard econ-footnote opening triggers ("We thank", "We are grateful to", "For helpful comments", and third-person and single-author variants), with two fallbacks (a name-led "<names> provided helpful comments" sentence, and a standalone end-of-paper "Acknowledgments" header for the Elsevier/JDE layout), and terminating the block at the earliest of a set of natural endpoints (an all-errors-are-our-own disclaimer, a competing-interests declaration, the JEL codes, or the start of the references). A hard cap of 2,200 characters bounds the damage when no terminator is found. The block is stored together with two rule-based pre-counts (a capitalized-bigram name candidate count and a seminar-keyword count) that serve only as a baseline for comparison against the Stage 17 figures, not as the headline numbers. The 2026-06-23 run located a block for 384 of the 392 RCTs (median block length 1,295 characters), with eight papers returning `no_block_found`; by source, 378 blocks were anchored on a standard trigger, four on an end-of-paper header, and two on a name-led fallback.

Stage 17 (`scripts/17_ack_classify.py`) is the structured-counting pass. For every located block it shells out to headless `claude -p` (authenticating via the local subscription rather than a metered API key, as in Stages 3c and 6f; default model `claude-sonnet-4-5`, prompt version `ack-count-v1`), replacing the default system prompt with an extractor prompt that sorts the thanked entities into the required categories and returns counts as JSON. The model performs the entity sorting (distinguishing, for example, "David Atkin" the person from "seminar participants at Brown" the venue from "Innovations for Poverty Action" the institution), a task regex cannot do reliably; the counts are then tabulated deterministically in Python. The eight `no_block_found` papers are written with all-zero counts (a paper whose acknowledgments name no individuals and no venues is a valid zero, not a missing value), while any `no_pdf` or `pdf_error` rows are passed through with blank counts and excluded from the analysis denominator. The script is resumable, checkpointing every ten calls and recording the model and prompt version per row. The run was completed on 2026-06-23 across three sittings: an initial overnight pass classified 140 blocks cleanly (zero call errors) before the machine entered sleep, after which the woken session degraded into a cluster of `claude` CLI process crashes (Windows exit code 0xC0000409) and a 180-second timeout that stalled progress, and two resumed passes the following morning completed the remainder. We assess the crash cluster as an artifact of the degraded post-sleep session rather than of the classification itself (the calls succeeded reliably whenever the machine was awake, 140 consecutively at the outset and 37 consecutively in the final pass), and a bounded retry-with-backoff (three attempts) was added to `call_claude` so that a transient subprocess crash self-recovers within a run rather than stranding the row as `call_error`. The final classification covers all 392 RCTs with no row left in error: 384 blocks classified `ok` and the eight `no_block_found` papers written as valid zeros, with no `no_pdf` or `pdf_error` rows in this corpus.

The headline outturn (analysis sample of all 392 RCTs, the eight no-block papers contributing zeros) is as follows. The mean number of individuals thanked for comments is 8.9 per paper, with a median of 6.5, a ninetieth percentile of 22, and a maximum of 46; 87 papers (22 percent) thank no named individual for comments at all. The mean number of distinct named seminars and venues is 4.0 per paper, but the distribution is markedly right-skewed (the median is 0, the ninetieth percentile is 13, and the maximum is 33), with 208 papers (53 percent) naming no venue and a further 89 papers (23 percent) flagging at least one vague, unnamed seminar reference (`seminars_unspecified`) that is deliberately not counted; the mean of 4.0 should accordingly be read as driven by a minority of papers that enumerate a long seminar circuit rather than as a typical value. ## 12. Subnational poverty and inequality matching (Stages 20-23)

A further line of analysis, begun 2026-07-22, aims to characterize the subnational settings in which our development RCTs are fielded by matching each trial's study site to the World Bank's subnational poverty, inequality, and multidimensional-deprivation indicators. The motivation is descriptive in the first instance (are development RCTs concentrated in the poorer or the less-poor regions of the countries that host them, and how does the local poverty context vary across the sample), with an eye to a later question of external validity (whether the places that host trials are representative of their national poverty distributions). The exercise reuses the full-text corpus and the DOI-to-PDF map already assembled for the IRB and acknowledgments work (403 PDFs; `data/irb_mentions.csv`), so no new PDF matching is required. As of 2026-10-21 the deterministic groundwork (Stage 20) is complete; site extraction has been completed without an API key, through a deterministic keyword pass followed by an in-session subagent pass (Stages 21b-21d, Section 12.8), and fieldwork years have been attached from the AEA RCT Registry (Stage 21e); the merge and figures (Stages 22-23) are specified but not yet written. Sections 12.4-12.7 record the original API-based design and the July blocker, and are retained for the record; Section 12.8 supersedes them as the current state. This section is intended to be sufficient to resume the work cold.

### 12.1 The World Bank AM25 subnational data

The input is the World Bank Poverty Global Practice's AM25 release (Fall 2025 vintage), downloaded 2026-07-22 to `World Bank subnational data/` (not committed; large and externally sourced). It comprises three artifacts. The first, `AM25_-_SPID_data.xlsx` (the Subnational Poverty and Inequality Database), carries roughly 115,000 rows on a `Data` sheet with a companion `Dictionary` sheet; its indicators are the poverty headcount ratios at the $3.00, $4.20, and $8.30 lines (2021 PPP; `poor300`, `poor420`, `poor830`), the survey mean and median consumption or income per capita (2021 PPP; `mean2021`, `median`), the Gini and Theil indices (`gini`, `theil`), and the prosperity gap (`prosgap2021`). The second, `AM25_-_Subnational_MPM.xlsx` (the Multidimensional Poverty Measure), carries roughly 9,900 rows at the admin-1 level, adding deprivation rates in monetary poverty, educational attainment and enrollment, electricity, sanitation, and drinking water (`dep_poor1`, `dep_educ_com`, `dep_educ_enr`, `dep_infra_elec`, `dep_infra_imps`, `dep_infra_impw`) and the multidimensional-poverty headcount ratio (`mdpoor_i1`). The third, `AM25_MASTER.ZIP`, is the global subnational shapefile and geopackage (`am25_subnat_em.{shp,dbf,prj,shx,gpkg}`) to which the tabular data key, retained for later mapping but not needed for the tabular merge.

Two structural features of the SPID file govern everything downstream. First, every geographic row carries a `geo_code` of the form `{ISO3}_{vintage}_{LEVELTAG}_{id}` (for example `AGO_2015_GAUL1_399`), where the third underscore-delimited field is the shapefile administrative level — `GAUL1`, `GADM1`, `NUTS2`, or `NSO1` for the first subnational level (admin-1: states, provinces, regions); `GAUL2`, `GADM2`, or `NUTS3` for the second (admin-2: districts, departments); and `GAULx`, `GADMx`, `NUTSx`, or `UNx` for a survey-imposed grouping of several admin-1 units, which is *coarser* than admin-1 — together with a human-readable `sample` name (for example "Benguela"). Second, the SPID `Data` sheet is disaggregated not only geographically but also by a demographic dimension (`data`/`data_group` taking values such as `agegroup3`, `Gender`, and `ALL`); only the roughly 17,000 rows with `data == 'ALL'` are the geography-only rows to which we match, and there are multiple survey years per country (`rep_year` spanning 1989-2024), so a year-selection rule is required (Section 12.3).

### 12.2 Stage 20 — coverage profiling and the level-of-aggregation finding

`scripts/20_wb_coverage_profile.py` is a deterministic (no-LLM) script that reads the SPID `Data` sheet and, restricting to the geography-only (`data == 'ALL'`) rows and to the 66 countries that host our RCT sample, determines for each country the finest geographic level at which the WB data actually tiles it. The operative definition of "finest usable level" (recorded as `matching_level`) is the `LEVELTAG` with the *most distinct units*, not the numerically-deepest tag. This distinction is substantive: several countries carry a single stray admin-2 unit (typically a separately-identified capital district) atop an otherwise complete admin-1 partition, and selecting the deepest tag would wrongly flip such a country to admin-2; taking the level with the most units correctly returns admin-1 for those, admin-2 for the countries the WB genuinely tiles at district level, and the coarse grouping for those offered only at `GAULx`. The script writes two outputs: `data/wb_subnat_coverage_profile.csv` (one row per RCT country, with `matching_level`, the unit count, all levels present with their counts, and the year span) and `data/wb_subnat_gazetteer.csv` (994 rows, one per named WB unit at each country's matching level: `iso3`, `matching_level`, `geo_code`, `unit_name`). The gazetteer is the controlled vocabulary that Stage 21 hands to the model, so that extracted site names map directly onto WB-canonical names and the Stage-22 merge is mostly exact rather than fuzzy.

The profiling resolves the level-of-aggregation uncertainty that motivated the exercise: the level is predominantly admin-1 but varies meaningfully across our study countries, falling into four buckets.

| Bucket | Matching level | What extraction can recover | RCT countries (RCT n) |
|--------|----------------|-----------------------------|-----------------------|
| Admin-1 (the majority) | `GAUL1` / `GADM1` / `NSO1` | State / province / region | India (63), Kenya (29), Bangladesh (20), Ghana (19), Tanzania (17), Pakistan (17), Mexico (14), Peru (9), Nigeria (7), and most others |
| Admin-2 / district | `GAUL2` | District / department | Malawi (15), Sierra Leone (9), Rwanda (7), Philippines (5), Sri Lanka (2) |
| Grouped, coarser than admin-1 | `GAULx` | Only a broad multi-district macro-region | Uganda (20), Uruguay (3), Argentina (3), Nicaragua (2), Jordan (2), Vietnam (1), Tunisia (1), Honduras (1) |
| Not covered | — | No match possible | China (14), Afghanistan (2), Saudi Arabia (1) |

Two features of this distribution bear directly on interpretation and should be carried forward. First, Uganda — with 20 RCTs, the third-largest country cell in the sample — resolves only to four macro-regions, each a bundle of roughly twenty-five districts, so those matches will be coarse irrespective of how precisely the papers name their sites. Second, China's 14 RCTs have no WB subnational data at all (the SPID release does not include China), and Afghanistan and Saudi Arabia are likewise absent. Turkey (8 RCTs) and North Macedonia (1) are carried on the European NUTS hierarchy (Turkey at `NUTS2`, twenty-six statistical regions) rather than the GAUL layers, which is admin-1-equivalent for our purposes. Taken together, the uncovered countries (17 RCTs) and the grouped-only countries (roughly 30 RCTs) mean that on the order of an eighth of the sample will match only coarsely or not at all; the clean single-admin-unit denominator will be well under 300, and we intend to report it transparently rather than suppress it.

### 12.3 Scoping decisions (project lead, 2026-07-22)

Three decisions were taken at the outset and are recorded here. First, on the geographic level to target: rather than a uniform admin-1 or admin-2 rule, we extract to match whatever resolution the WB actually provides for each country (the country-adaptive `matching_level` from Stage 20), so that no effort is spent extracting district or village detail the WB cannot use, and finer detail is extracted only where the WB resolves it. Second, on which of the multiple WB survey years to attach: the survey year nearest to each trial's fieldwork period, so that the poverty snapshot is roughly contemporaneous with the study (this is the reason Stage 21 extracts the fieldwork years, not merely the site). Third, on studies that do not map to a single unit: each RCT is flagged single-region, multi-region, or nationwide/unspecified, and only the single-region trials carry a clean one-to-one match; the multi-region and nationwide trials are carried with their flag so that the analysis denominator stays transparent.

### 12.4 Stage 21 — subnational site extraction (LLM; written, not yet run)

`scripts/21_site_extract.py` is the interpretive pass. For each single-country RCT whose study country is WB-covered, it reads the paper's full text (via poppler's `pdftotext`, reusing the Stage 16 approach; the leading 32,000 characters, which reliably contain the abstract, introduction, and context or experimental-design sections where the site is named) and asks the model to extract the study site at that country's target level, the site scope (single-region / multi-region / nationwide / unspecified), and the fieldwork years. The country's gazetteer (Stage 20) is supplied in the prompt as the admissible-unit vocabulary, with an instruction to roll any finer place named in the paper (a village, a town) up to the containing target-level unit and to prefer "unspecified" over a fabricated match. The output is `data/site_extracted.csv`, one row per RCT, carrying the matched WB unit name(s), the raw site phrase, the scope flag, the fieldwork years, a confidence and a one-sentence justification, and the status field `extract_status` in {`ok`, `not_single_country`, `country_not_covered`, `no_pdf`, `pdf_error`, `call_error`}. The script is resumable (it skips rows already `ok`), checkpoints every ten calls, and stamps the model and prompt version (`site-extract-v1`) per row.

The disposition of the 392 RCTs into this stage is as follows: 350 form the LLM work-list (single-country, WB-covered, with a matched PDF), comprising 288 admin-1, 36 admin-2, and 26 grouped-region trials; 25 are set aside as not-single-country (cross-country, or with no single resolvable study country); and 17 are set aside as country-not-covered (China 14, Afghanistan 2, Saudi Arabia 1). The non-work-list rows are written to the output with their status and no LLM call.

### 12.8 Site extraction completed in-session, and fieldwork years (2026-10-20 to 2026-10-21)

Because the project lead preferred to draw on the Claude Code subscription rather than purchase API credits, Stage 21 was run through a combination of Routes C and B (Section 12.5) rather than through `21_site_extract.py`, which remains unrun. The pipeline has four steps. `scripts/21b_site_match_local.py` is a deterministic keyword pass over the full text of the 350 work-list papers: it matches the country's gazetteer names (title-case, accent-folded, with generic names such as "Central" or "Plateau" counted only beside an administrative noun), a curated alias table (spelling variants, English renderings, and major cities rolled up to their unit), and a set of SUPPLEMENTARY units (below), and it classifies each paper as resolved_single (121), dominant_single (18), multi_candidate (81), single_weak (31), weak_only (25), or no_hit (74); output `data/site_local_matched.csv`. `scripts/21c_site_session_prep.py` writes per-paper text files and batch files to `data/_site_session/`, and Sonnet subagents launched from the session then either verified the 139 resolved and dominant proposals against the paper text or extracted the site afresh for the remaining 211, writing one JSON per paper to `data/_site_session/out/`. A second pass (`RECHECK=1`) re-read the full text, rather than the leading 32,000 characters, for the 67 papers left unspecified or handled by keyword search alone, since several agents reported that the setting section fell beyond the first window. `scripts/21d_site_session_merge.py` validates every unit name against the admissible list and writes `data/site_extracted.csv` in the Stage-21 column layout, stamped `llm_model = claude-code-session`.

The verification step corrected 15 of the 139 keyword proposals (roughly 11 percent), chiefly where the paper also named districts lying in a second unit or where the matched name was only a partner organization. The final disposition of the 350 papers is 180 single_region, 93 multi_region (median three units), 38 nationwide, and 39 unspecified; the agents rated 256 answers high confidence, 80 medium (most often where a town or district was rolled up to its unit from geographic knowledge rather than from the text), and 14 low. The unspecified papers generally name their sites only on a map or in an appendix not bundled with the PDF. Two papers were flagged as possible upstream errors: `10.1257/aer.20201661` (coded as Peru, but with no Peruvian site) and `10.1016/j.jdeveco.2022.102942` (Lebanon; a regression-discontinuity design rather than an RCT), both candidates for the Not-RCT correction list.

The exercise surfaced a limitation of Stage 20. The gazetteer retains only units at each country's matching level, but the SPID carries some regions at another level that fills a gap in that tiling: Pakistan's Punjab and Khyber Pakhtunkhwa (GAULx groupings; the GAUL1 layer holds only Sindh and Balochistan), Bogotá and Cundinamarca, Maputo, Greater Monrovia, Togo's Maritime region, Sierra Leone's Western Area, and the capital areas of Paraguay, Nicaragua, Tunisia, and Jordan, among others. These are carried as `SUPPLEMENTARY` units in `21b_site_match_local.py` (18 single-region papers rely on one), the `unit_levels` column of `site_extracted.csv` records each unit's SPID level, and Stage 22 must resolve them at that level. The proper fix belongs in Stage 20.

Fieldwork years are attached by `scripts/21e_fieldwork_years.py`, which reads the AEA RCT Registry identifiers detected by Stage 24 and looks them up in a full registry export downloaded into the project on 2026-10-21 (`data/trials.csv`, 12,932 trials; per Section 3, earlier exports held in other Dropbox folders are not used). The start year is the registered intervention start date (else the trial start date) and the end year the intervention end date (else the trial end date). All 221 papers carrying an AEA identifier are matched. Papers that print no identifier (many state that the trial is registered with the AEA without giving the number) are matched to the registry on title-word overlap plus author overlap with the registered PIs; every candidate is logged to `data/aea_title_matches.csv`, and a hand review on 2026-10-21 rejected six automatic matches (different trials, or follow-ups registered years after the fieldwork) and accepted twenty below-threshold candidates confirmed as the same trial (`TITLE_MATCH_REJECT` / `TITLE_MATCH_ACCEPT` in the script). For placed papers still undated, in-session subagents read the full text for the experiment's own fieldwork years (`21c` with `YEARS=1`; answers in `data/_site_session/years_out/`). The Stage-21b text hint (calendar years near "baseline" or "endline") is retained only as a last resort; it agrees with the registry start year exactly in 51 percent of the 139 papers where both exist and to within one year in 78 percent, and it disagrees with the subagent reading by five or more years in 7 of 53 cases. Among the 273 papers placed in one or more units, 155 carry registry years by identifier, 35 by title match, 81 from the paper text, and 2 no year (for these Stage 22 falls back on the publication year; the registry suggests a median lag of six years from fieldwork start to publication, with a 10th-90th percentile range of three to eleven). Long-run follow-ups of older trials carry wide spans (for example 1998-2021), so Stage 22 should anchor the survey-year match on the start year, or on an explicitly chosen reference year, rather than on the midpoint. Output `data/site_fieldwork_years.csv`; `21d` fills the fieldwork-year columns of `site_extracted.csv` from it, so 21e is run before 21d. The registry export is large (79 MB) and is not intended for version control.

### 12.10 Stage 22 — merge with the World Bank indicators (2026-10-21)

`scripts/22_site_wb_merge.py` attaches the SPID poverty and inequality indicators and the subnational MPM deprivation indicators to every site row of `data/site_extracted.csv` and, when present, of `data/site_extracted_multicountry.csv` (one row per paper and country; Section 12.9). Units are matched on the country code, the SPID `sample` name, and the level tag (the Stage-20 matching level, or the level of a SUPPLEMENTARY unit), rather than on `geo_code`, because the same region carries different codes across survey vintages. The reference year is the fieldwork start year from Stage 21e (publication year minus six where no year is known, flagged `year_rule = pub_minus_lag`); among the SPID surveys containing the site's units we take the one covering the most of them, then the one nearest the reference year, then the earlier, so that all units of a multi-region site are read from a single survey. MPM indicators are attached separately from the MPM survey nearest the reference year. Two boundary rules are encoded: a Telangana site with fieldwork before the 2014 bifurcation reads undivided Andhra Pradesh, and post-2014 Andhra Pradesh is also sought under the GAULx tag at which the 2022 survey carries it.

Because the SPID release carries neither national rows nor population weights, the site's relative position is measured within its own survey, whose geography-only rows tile the country: the unweighted percentile rank of the site's $3.00 (2021 PPP) headcount among the survey's regions (0 for the least poor, 1 for the poorest), the analogous rank for mean consumption or income, and the gap between the site's headcount and the unweighted regional mean. Multi-region sites take the unweighted mean across their units. The unweighted comparison is a limitation to be reported, since a populous poor region and a sparsely populated one count equally.

In the run of 2026-10-21, which includes the multi-country country-rows of Section 12.9, all 296 placed sites (273 single-country, 23 multi-country country-rows) matched an SPID survey and 294 also carry MPM indicators; 294 use the fieldwork start year and 2 the publication-lag fallback (the paper-text year pass of Section 12.8 was extended to the eight multi-country papers lacking a registry date; the 2 remaining are papers that state no calendar date at all). The survey year lies a median of one year from the reference year (90th percentile four years), but some gaps are large and structural, arising where the World Bank resolves the current administrative geography only in recent surveys: Kenya's counties (2015 onward; one 1998 trial matched 17 years later), Nepal's post-2015 provinces (2022 only), Philippine provinces, and Jordan (2010 the latest year). The `spid_year_gap` column records the gap for every site. Descriptively, and as a first look rather than a finding, the mean percentile rank of trial sites in their country's regional $3.00 headcount distribution is 0.43 (median 0.42, n = 296), and 42 percent of sites lie in the poorer half of their survey's regions; this is suggestive that trials are, if anything, somewhat more often fielded in the less-poor regions of their host countries, but the measure is unweighted, the regional grid is coarse in many countries, and we have not yet examined how the pattern varies with the level of geography, region, or journal tier. Outputs: `data/site_wb_merged.csv` (one row per site row, including unplaced and unextracted rows with their status) and `data/site_wb_merged_units.csv` (one row per matched unit, for audit). Stage 23 (figures and a validation sample) is described in Section 12.11.

### 12.11 Stage 23 — descriptive figures and validation sample (2026-10-21)

`scripts/23_site_charts.py` reads `data/site_wb_merged.csv` and writes four figures in the project's figure style. `fig39_site_coverage` gives the disposition of all 457 site rows (one per single-country RCT and one per country arm of a multi-country RCT): 195 placed in a single World Bank unit (43 percent), 101 in several (22 percent), 48 nationwide (11 percent), 68 not identifiable from the paper (15 percent), and 45 outside World Bank coverage or unresolved (10 percent). `fig40_site_poverty_rank` is the distribution of the 296 placed sites' percentile ranks in their survey's regional $3.00 headcount distribution, against the flat line expected if sites were drawn at random across regions; `fig41_site_rank_by_group` gives mean ranks with 95 percent intervals by journal tier and by level of geography; and `fig42_site_vs_regional_mean` plots each site's headcount against the unweighted mean of its survey's regions. The script also writes `data/site_wb_summary.csv` and a fixed-seed (42) validation draw of up to ten placed sites per extraction route (40 rows), `data/_site_validation_sample.csv`, with the paper's locating text and empty reviewer columns for a human check.

The descriptive pattern, which we regard as suggestive rather than established, is that trial sites lie somewhat more often in the less-poor regions of their countries: the mean rank is 0.43 (median 0.43; 0.5 would correspond to a region drawn at random), and 120 of 296 sites (41 percent) have a $3.00 headcount above their survey's regional mean. The distribution is not uniformly shifted; its most salient feature is a concentration in the least-poor decile (52 sites), which consists largely of capital or metropolitan regions (Nairobi, Punjab and Islamabad, the Kampala grouping, Dar es Salaam, Gauteng, Dakar, Greater Accra, Metro Manila), consistent with the share of urban and firm-based trials in the sample. By journal tier, the mean rank is 0.41 for the Top 5 (n = 66, 95 percent interval plus or minus 0.07), 0.40 for the other general-interest journals (n = 118, plus or minus 0.05), and 0.48 for JDE (n = 112, plus or minus 0.05); the JDE difference is consistent with the journal publishing more rural trials, but the intervals overlap with the Top 5 and we have not tested it formally. Three caveats bound these statements: the rank is unweighted by population, the regional grid is coarse in many countries (so a district-level trial in a poor district of a less-poor province registers as less poor), and multi-region sites are averaged across their units.

## 13. Trial pre-registration and pre-analysis plans (Stages 24-25)

A further line of analysis, begun 2026-08-03, characterizes the research-transparency practices of the 392 RCTs along two dimensions: whether the trial is registered in a public trial registry, and whether the paper reports a pre-analysis plan (PAP). The motivation is descriptive, in a spirit parallel to the IRB attribution (Stages 12-15): to document the diffusion of the pre-specification norms that have become an increasingly salient expectation at the leading outlets (the AEA RCT Registry opened in 2013), and how the practice varies across journal tier and over the 2021-2025 window. The exercise reuses the full-text corpus and the DOI-to-PDF map already assembled for the IRB and acknowledgments work (the `matched_file` column of `data/irb_mentions.csv`, populated for all 392 RCTs), so no new PDF matching is required.

The design is deliberately fully deterministic — no LLM call is involved — which distinguishes it from the site-extraction work (Stage 21) that remains blocked pending API credits (Section 12.5), and which is defensible here because both quantities of interest are self-identifying in the text. A trial registration leaves a high-precision fingerprint (a registry identifier of fixed form — `AEARCTR-0003555`, `NCT01234567`, `ISRCTN75964374`, `PACTR...`, `CTRI/YYYY/NN/NNNNNN`, `ACTRN...`, `DRKS...` — or the named registry, "AEA RCT Registry" / "socialscienceregistry.org"), and a pre-analysis plan is reported in a small, stable vocabulary ("pre-analysis plan", "pre-registered analysis plan", "pre-specified analysis plan"). We assess that a keyed-LLM refinement sibling could be added later to adjudicate the residual (as `13_irb_classify.py` complements the deterministic `13_irb_classify_local.py`), but it is not required for the headline.

### Stage 24 — pre-registration / PAP scanner

`scripts/24_prereg_extract.py` reads each RCT's PDF via poppler `pdftotext` (as in Stage 16, chosen for its clean UTF-8 and speed — the full 392-RCT pass runs in roughly four minutes, against the ~40 the pdfplumber IRB scan took), splits on the form-feed to recover page numbers, and runs two scans per page: a whitespace-collapsed scan (joins phrases split across line breaks) and a "despaced" scan (all whitespace stripped, lowercased) that recovers the Elsevier/JDE lost-inter-word-space case. It detects (i) structured registry identifiers by regex, (ii) named registries even where no identifier is printed, and (iii) pre-analysis-plan phrasing. Two platforms whose bare name is overloaded are handled specially, counting only when a registration cue sits within 110 characters: OSF (osf.io links in economics papers are frequently preprint or supplementary-material DOIs rather than registrations) and EGAP (Evidence in Governance and Politics, which is simultaneously a registry, a funder — the "EGAP Metaketa initiative" — a conference series, and an author affiliation; a first pass with a bare `EGAP` match wrongly flagged fifteen papers, of which only nine survive the cue requirement, and the six removed were funder, conference, or affiliation mentions). The headline classification is folded in deterministically. Output: `data/prereg_classified.csv`, one row per RCT, carrying `registered` (boolean), the matched `registries` and `registry_ids`, `has_pap` (boolean), two supporting signals (`prereg_wording`, `analysis_plan_any`), a per-paper `prereg_class`, audit snippets, and `extraction_status`. The script is resumable and honours a `SMOKE_N` flag.

### Stage 25 — figures, summary, and validation sample

`scripts/25_prereg_charts.py` reads the classification (analysis sample: the 392 rows with `extraction_status == "ok"`, all of which carry a readable PDF in this run) and writes four figures — `fig35_prereg_overview` (overall shares), `fig36_prereg_by_year` (registration and PAP shares by publication year), `fig37_prereg_by_tier` (by the Top-5 / other-general-interest / JDE tiers shared with the funders and acknowledgments analyses), and `fig38_registry_composition` (papers by registry) — together with `data/prereg_summary.csv` (overall, by-tier, and by-year rows) and `data/_prereg_validation_sample.csv`, a fixed-seed (42) stratified draw of thirty-two papers (up to eight per `prereg_class`) with the audit snippets joined back in, so that a human coder can verify the deterministic classification against the source text.

### 13.1 Outturn (2026-08-03 run)

Of the 392 RCTs, all of which carry a readable full-text PDF, **293 (74.7 percent) are registered in a public trial registry** and **150 (38.3 percent) report a pre-analysis plan**. The four-way classification is 131 papers (33.4 percent) both registered and with a PAP, 162 (41.3 percent) registered without a PAP, 19 (4.8 percent) with a PAP but no detected registry, and 80 (20.4 percent) with neither. Registry use is overwhelmingly concentrated in the AEA RCT Registry (282 of the 293 registered papers), with a long tail of EGAP (9), ClinicalTrials.gov (5), ISRCTN (4), OSF (4), PACTR (1), and AsPredicted (1); registries can co-occur, so these sum to more than 293. We caution that the registered share is a lower bound on registration and the PAP share a lower bound on PAP filing, because both rely on the practice being reported in the published text; a trial registered but not mentioned in the PDF (or mentioned only in an online appendix not captured by the full-text extraction) would be missed, and the `neither` category should accordingly be read as "no transparency statement located in the text" rather than as a confirmed absence.

Two patterns are salient. First, registration rose over the window while PAP reporting did not: the registered share moved from 68 percent in 2021 (and again in 2022) to 73, 85, and 79 percent in 2023-2025, whereas the PAP share was essentially flat across the same years (39, 36, 38, 37, and 41 percent). This divergence is suggestive that registration has become a near-consolidated norm while the more demanding practice of filing a pre-analysis plan has not diffused at the same pace, though the annual cell sizes are modest (between 69 and 84 papers) and the figures should be treated as descriptive only. Second, the two dimensions order differently across journal tiers: registration is somewhat higher in the general-interest journals (79 percent in the Top 5 and 80 percent in the other general-interest outlets) than in the JDE (67 percent), whereas PAP reporting is, if anything, higher in the JDE (42 percent) than in the Top 5 (36 percent) or the other general-interest journals (35 percent). We assess that this inversion is consistent with registration being driven partly by the submission requirements of the most selective outlets while PAP filing tracks the field-experiment-heavy composition of the JDE, but we cannot from these descriptive data separate a journal-policy channel from a study-design or author-norms channel.

### 13.2 How to reproduce

From the project root, with `$PY` the interpreter in Section 3: `& $PY scripts\24_prereg_extract.py` (a `SMOKE_N=15` pass first is advisable to inspect snippets; the full pass is deterministic and takes ~4 minutes, needs no API key, and requires only poppler `pdftotext`, already used by Stage 16), then `& $PY scripts\25_prereg_charts.py` for the figures and summary. To regenerate at a different snippet width, move `data/prereg_classified.csv` aside first so every row is rebuilt (the resume logic reuses stored snippets). The one judgment call worth re-checking on any re-run is the EGAP / OSF cue window (constants `CUE_WINDOW` and `CUE_RE` at the top of Stage 24); the fixed-seed validation sample in `data/_prereg_validation_sample.csv` is the intended vehicle for that check.
